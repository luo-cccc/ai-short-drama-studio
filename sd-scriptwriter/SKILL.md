# 场景剧本创作

## 职责与输入

根据用户的素材、品类、篇幅和限制创作剧本。已有素材或明确约定可直接沿用，只询问影响创作的缺失信息。完整项目先明确主线、人物关系和结尾回报，再展开场次；单场修改按用户范围交付。

本模块提供创作指引，不自带市场数据库、版权识别、平台审查或媒体生成工具。涉及事实、素材权利和发布要求时，标明依据和仍需确认的信息。

## 工作流程

1. 整理素材：分清已有事实、允许改编的部分、必须保留的事件与台词。
2. 建立全局设定：人物、地点、道具、风格、时间线。多集项目同时记录跨集固定设定。
3. 规划大纲：每个段落写清目标、阻力、变化和结果；场次由时空与叙事任务划分。
4. 写场景剧本：以动作、对话和声音推进；场次头交代时空，动作建立位置与视线关系。
5. 按质量清单人工审阅，再交付用户指定范围。审阅问题直接修订内容，不把自检过程混入剧本正文。

具体方法见 [执行规则](references/execution-rules.md)，设定与审阅见 [质量清单](references/quality-gates.md)。跨模块边界以 [规则权威表](../references/rule-authority.md) 为准。

## 输出

完整场景剧本按以下顺序组织；只请求梗概、人物或单场时，仅交付相应部分：

1. 项目全局设定：项目元信息、人物、场景、道具与跨集约定。
2. 剧本总纲：风格、主线冲突、节奏、场次与转场设计；多集时补系列规划。
3. 核心梗。
4. 故事梗概。
5. 一句话卖点。
6. 人物小传。
7. 剧本大纲。
8. 视听元素总览：声音方向与关键声音事件。
9. 剧本正文。

独立文学剧本保存为“片名_场景剧本.md”。使用自然语言正文，不加入模型参数、生成提示词、分镜表或虚构的审查通过声明。

### 单场戏格式

~~~text
01-01  昏  阴  外  旧院门

出场人物：晚晴
道具：铜钥匙

△ 晚晴停在门外石阶上，面向入口右侧门扇，目光沿门闩移向新锁。
晚晴（压低声音，手指停在锁旁）：门锁换过了。
△ 她收回手，沿木门边缘俯身查看。

【音效：手指碰到锁环，铜件短促轻响。】
【转场：声音延续，下一场承接她查看门框的动作。】
~~~

场次连续编号；动作以△开头；台词标明说话者。OS、旁白、字幕、音乐仅在剧情确有需要时添加，不填“无”占位。光照可用可见效果交代，摄影机、焦距与运镜留给分镜设计。

## 进入结构化制作

剧本确认后，人工整理资产、剧情节拍与原始台词，按 [项目数据契约](../references/project-data.md) 建立 project.json。保留原剧本作为创作依据，JSON 不自动解析或完整保存九板块文学文档。

当前 Schema 和项目 QC 面向包含分镜、提示词的完整制作数据；仅完成剧本或 Phase 1 的 JSON 草稿不能据此宣称已通过完整项目 QC。下游以稳定 ID 关联节拍与台词，创作修改回到原始内容和数据源，不在导出 Markdown 中单独改写。
