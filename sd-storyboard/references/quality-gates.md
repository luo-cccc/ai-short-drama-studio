# 分镜审阅与 QC 分工

跨模块格式以 [规则权威表](../../references/rule-authority.md) 为准。这里列出脚本能力与需人工判断的内容，避免把检查清单误当成已经实现的检测程序。

## 程序检查

完整 project.json 的 QC 包含：

- Schema 形状、实体 ID、引用类型与局部素材位绑定。
- 剧情节拍是否被分镜认领，节拍涉及的资产是否承接。
- 台词使用次数、所属节拍、说话角色、顺序与文字对账；忽略标点和空白的规则以数据契约为准。
- 结构化镜头与动态提示词的编号、时间戳、总时长及台词执行对账。
- 上游依赖快照、循环依赖和失效传播；提供历史基线时检查 ID 删除、版本回退及内容变更未增版。
- 实际提示词中的占位符、机制标签、部分参数与方位词、参考声明、T6B 继承范围和动态情绪层。

独立 Markdown 只逐提示词代码块检查，不能据此完成节拍覆盖、资产身份或修改追溯。风格段识别、字数和尾约束等部分检查是提示性规则，WARN 需要审阅，不等于错误已修复。命令、输入范围和退出码见 [项目数据契约](../../references/project-data.md)。

review.status 是记录，不是脚本专业审批门控。完整数据可导出未审查草稿；阶段不完整的 JSON 则受当前 Schema 必填限制。实际媒体是否存在、角色是否相似、表演是否成立，需要外部生成与审片。

## 人工审阅

### 叙事与时间

- 原剧本事件、动作、台词和转折是否完整落地，而不只是 ID 已被认领？
- 计划时长是否足以容纳动作、台词和停顿？试听之后是否需要拆镜或调整？
- 开头是否建立当前状态，结尾是否完成信息变化，并与下一镜连接？
- 是否把复杂事件堆在同一时刻，导致观看或生成难以执行？

### 81 · 前置设计

八岗位决策有具体理由，9B 审阅记录真实；提示词与审阅后的设计一致。检查顺序和内容见 [design-9b.md](design-9b.md)。

### 82／83 · 关键帧与出场时序

T6 开头、结尾与动态文字的角色、位置、表情、道具和环境对应。后段才出现的道具或特效，不提前写成全程存在。抽取关键帧时核对其对应物理镜头，而不把九格强行变成九次切镜。

### 84／85／88 · AO 第一人称手部与方位

- **AO1 纯方位命名**：用画面中的入画方位与动作说明哪只手在操作，减少含糊的左右指代。
- **AO2 单方位锚定**：同一段连续操作保持关键手的入画位置；换角度时先重新建立参照。
- **AO3 配饰边界**：不要为区分手部凭空增加手表、戒指或护腕；原角色确有配饰时按设定保留。
- **AO4 翻转检查**：检查手掌朝向、握持点和接触面，不把“翻转手腕”等词当作解剖正确性的保证。
- **AO5 双手分工**：确有双手协作时明确各自任务，不需要时不额外添加动作。

FPV 俯仰需要角色头部、身体或载具运动的依据，并有可见参照物帮助理解。第三人称要区分角色左右与画面左右：背对镜头时同向，面对镜头时镜像，侧身时无稳定对应；必要时先说明朝向，再判断手部位置。这些是设计与审片事项，QC 没有解剖识别能力。

### 86 · 时间分配

按动作、信息和台词复杂度分配时长，不强制“末镜头永远最长”。具体比例由作品节奏决定；以实际播放和试听验证。

### 87 · 输出与问题说明

提示词块内只有投产文字，元数据、设计理由和检查结果放在块外。交付不附整套冗长的审查表，但对未解决问题清楚报告，不用“静默校验通过”替代真实状态。

### 89–94 · AP 故事板

- **AP1 角色基底**：同一角色跨格的外观、服饰结构和辨识细节一致，不在每格重述整份设定。
- **AP2 场景与风格基底**：空间定锚物保持；彩色提案版与黑白线稿投喂版不混用继承规则。
- **AP3 关键帧对应**：九格表现计划中的静态节点，首尾与动态执行对照。
- **AP4 静态镜头语言**：各格说明景别、机位、焦距光圈、构图、景深焦点和遮挡关系；不要用运镜代替凝固画面。
- **AP5 格内画幅**：网格、单元和画面区的大小比例一致，图像返回后人工核对。
- **AP6 外画幅**：T6／T6B 整体与格内画幅按 R-ASPECT-001 分别处理。

同时核对图板信息栏、Shot 编号和空间调度图的可读性：角色起止点、路径、机位与图例对应；叙事画面不混入说明线条或文字。特效展示区只在确有需要时保留。具体布局比例和字段见静态模板，不在本清单重复定义。

### 95／96 · 提示词结构与文字

按实际模板核对各语义层、参考声明、声音、镜头与收尾约束。动态④情绪目标与⑤风格应分别表达；画面动作段与声音、情绪目标的语言边界不同。删除未填占位、编辑注释和跨模板省略指令，保留必要的图板标签和素材引用。

## 修改后复核

先更新源数据及实际制作内容，重做受影响的设计和提示词后再捕获依赖快照。检查 JSON 与导出文档的内容关系，不能只刷新指纹来消除失效错误。媒体生成后仍需核对身份、动作、空间、光影和声音，不把文本 QC 当成成片验收。
