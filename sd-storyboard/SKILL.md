# 分镜设计与制作规划

## 输入与职责

输入为场景剧本、人物/场景/道具设定、画幅、目标时长和用户已确认的创作约定。没有完整剧本时先补齐所需内容，不从人物简介自行编造执行台词。

分镜负责认领剧情节拍、规划镜头与声音、组织资产引用，并把审阅后的设计转为静态与动态提示词。仓库脚本校验数据和导出 Markdown，不调用图像、视频、配音模型，也不自动完成八岗位审查。

跨模块规则见 [规则权威表](../references/rule-authority.md)，数据与命令见 [项目数据契约](../references/project-data.md)。

## 工作流程

### Phase 1 · 全局规划与草稿审阅

1. 整理资产、剧情节拍与原始台词，确定风格、画幅和系列连续性。
2. 根据剧情量、动作和空间变化拆分制作片段；不删剧情去适配预设镜数。
3. 规划全局静态资产及每镜引用，选用对应模板。
4. 为各分镜建立八岗位设计与总表草稿，提交本阶段约定的审阅对象。

当前 JSON Schema 要求分镜与提示词非空。只有剧本或资产清单的阶段草稿不能通过完整项目 QC；先人工审阅，数据齐备后再执行正式检查。

### Phase 2 · 逐镜设计与交付

1. 按 [9B 八岗位设计](references/design-9b.md) 完成叙事、摄影、光影、动作、空间、台词、声音与特效判断。
2. 使用 [分镜规则](references/storyboard-rules.md) 核对衔接、轴线、关键帧和声音关系。
3. 调用静态与动态模块的模板编写提示词，记录素材位与稳定资产 ID。
4. 更新完整 project.json，重做受影响的内容后显式捕获依赖快照，运行 QC，再导出。
5. 按用户已约定的逐镜或批次方式审阅；已有授权不重复请求。

专业审查状态写入 review.status。脚本只记录并显示该状态，不把 approved 作为导出门控；允许导出“未审查”草稿，不得把它标为已完成专业审查或已获用户批准。

## 模板分工

| 制作对象 | 模板与所属模块 |
|---|---|
| 全局角色、道具、场景 | 静态模块 T1、T2、T3；扩图按需用 T4 |
| 场景空间参考 | 静态模块 T5，可按空间与视角需求复用 |
| 故事板 | 静态模块 T6 彩色提案版，或 T6B 黑白线稿投喂版 |
| 文生、图生、混合视频提示词 | 动态模块 T7、T8、T9；分镜默认 T9 |

模板正文、参考继承与画幅只在 [静态模板](../sd-static-assets/references/templates.md)、[动态模板](../sd-dynamic-video/references/templates.md) 和规则权威表维护。本模块不复制字段定义。

## 输出

独立文学剧本由编剧模块交付。完整制作数据通过 QC 后由导出器生成：

- project.md：项目设定、原始节拍与台词、全局静态提示词、总分镜表。
- SHOT-ID_分镜.md：分镜设计思维、静态提示词、动态提示词、配音与音效脚本、素材位对照与资产清单，共五章。

导出器在每个提示词代码块外写模板与时长元数据；块内只保留实际提示词。设计思维按八岗位分别展示知识要点与本镜决策。资产“已定义”与图片/视频“已生成”是不同状态，不能从 JSON 引用推断媒体已存在。

## 总分镜总表规范

15个字段：镜号、合规时长档位、分镜核心功能、核心剧情梗概、分镜头数量、切镜节奏、核心镜头语言设计、核心光影基调、关键音频节点、转场设计、核心配音台词内容、参考图资产、9B设计编号、9B-1B审查状态、备注。

字段由导出器从项目数据生成；不在 Markdown 中另维护一份互相独立的总表。
