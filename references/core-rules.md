# 制作审查索引

本文件集中说明制作时需要核对的事项，不重复定义模板字段或程序规则。跨模块约定见 [rule-authority.md](rule-authority.md)，自动检查范围见 [project-data.md](project-data.md)。编号用于对应各模块中的制作原则引用。

## 审查职责

Agent与制作人员核对叙事、表演、空间和风格；Python工具核对数据关系与文本格式。先区分问题属于哪一层，再使用对应模板或检查方法。通过文本QC不等于已验证实际生成画面。

| 编号 | 核对事项 | 依据与方法 |
|---|---|---|
| 1 | 角色、场景与风格一致 | 复用项目定义，检查当前镜头的可见特征；实际成图需逐张比对 |
| 2 | 制作顺序 | 依据现有材料进入相应模块，未解决的上游改动应传递到下游 |
| 3 | 具体信息 | 清除交付提示词中的占位符，给画面元素明确的可见状态 |
| 4 | 视觉、声音与设计目的的边界 | 按R-VISUAL-001区分画面、情绪目标和音轨，避免把设计解释混入画面段 |
| 5 | 素材来源 | 记录用户提供素材与引用范围；本仓库不执行版权检索或平台审核 |
| 6 | 资产复用 | 用稳定ID登记角色、场景、道具；复用全局静态提示词，避免重复定义 |
| 7 | 提示词可复制 | 每条独立代码块，仅保留当前生成任务所需内容 |
| 8 | 修改追溯 | 依据R-DATA-001检查直接和传递依赖；重捕快照前先完成实际修订 |
| 9 | 模板完整 | 使用对应templates.md的字段，不把模板写作说明留在实际提示词中 |
| 10 | 阶段审阅 | 按用户约定审查全局设定与逐镜设计；审批是工作流程，不由QC脚本执行 |
| 11 | 空间与动作连续 | 检查位置、视线、动作过渡、光影与声音衔接；方法见分镜规则 |
| 12 | 模块分工 | 编剧处理剧情，分镜处理设计，静态与动态模块处理各自提示词 |
| 13 | 档案与投产参数 | 人物比例和摄影参数分别按R-PARAM-001处理，不把全部数字一律删除 |
| 14 | 画面叙事 | 观众需有可见的动作、物体或反应作参照；动作结果应有前置过程 |
| 15 | 剧本节奏与人物 | 采用编剧模块的方法审阅钩子、冲突、对白与人物行动；节奏按具体题材调整 |
| 16 | 场景基础光与叙事光 | T3/T5表达空间常量，动态镜头承担叙事光影；按R-LIGHT-001处理 |
| 17 | 场景纵深 | 描述空间结构、材质与可见动态，按前景到远端组织；人物感受留在适当的剧本文字中 |
| 18 | 机位与空间 | 依据空间大小和遮挡选择机位，方法见静态规则的场景机位匹配 |
| 19 | 动态提示词组织 | 层序、参考声明、镜头时间戳分别按R-STRUCT-002、R-REF-001、R-TIME-001 |
| 20 | 镜头块内容 | 使用镜头运动、人物动作、可见表情和环境变化推进；对白与音效置于对应动作发生处 |
| 21 | 方位参照 | 多视角空间图用建筑相对方位；单镜头按所选画面/建筑参照保持一致，必要时交代切镜后的参照变化 |
| 22 | 分镜设计 | 使用9B八岗位方法交代设计依据与决策；没有特效也要写明该岗位结论 |
| 23 | 静态设计 | 检查构图、色彩光影、定格姿态、视觉焦点与资产用途；不要把连续动作塞进单张参考图 |
| 24 | 风格与布光 | 项目风格作为共享输入，镜头光影设计与其协调；四光位按动态模板表达，实际效果仍需审片 |
| 25 | 交付净化 | 移除管理注记、跨模板文字指令与未替换占位；必要的信息栏、Shot编号和参考声明按各模板范围保留 |
